# Как оценивать стратегии

Одинаковые шкалы делают предположения о вариантах видимыми. У оценок разная природа. Источник может задавать число напрямую, объяснять границу экспертного диапазона или как раз указывать, чего мы пока не знаем. В карточке каждого критерия это видно отдельно.

## До расчёта

1. Запиши варианты с возражениями в `state.json`. В `evidence.md` дай каждому основанию строку таблицы с ID в первой ячейке, например `| E1 | Бриф, стр. 4 | … |`. Поддержаны и пункты вида `- **E1, факт.** …`. Для каждого ID укажи источник и точный локатор.
2. В папке нового дела создай заготовку. Команда печатает текущие варианты и пустые поля. Перенаправление в существующий файл перезаписывает его, поэтому сначала проверь наличие предыдущей оценки.

```sh
python3 tools/score.py work/my-case --init > work/my-case/scoring.json
```

3. Определи общий горизонт и меру каждой категории в `measures`. У клиентского результата укажи минимально значимое изменение, у экономики — целевой дополнительный вклад, у срока — крайний срок и необходимый ресурс, у новых знаний — какое следующее решение нужно принять. Если порог открыт, отметь это и учти в диапазоне. Для всех вариантов действуют одни меры.
4. Задай обязательные условия в `gates`, например право на действие или подтверждённый доступ к данным. Для каждого варианта поставь каждому условию `pass`, `pending`, `fail` или `na`. Опиши причину. Для выполненного, нарушенного и неприменимого условия укажи свидетельство. Неподтверждённая смета может ухудшать исполнимость. Жёстким условием она становится, когда выполнение конкретного шага требует одобрения бюджета.
5. По каждому критерию задай диапазон двух целых от 0 до 4, `basis` (`evidence` или `assumption`), краткое объяснение и ссылки `refs` на реестр. Например, `{"band":[2,2],"basis":"evidence","reason":"Обычное обслуживание сравнивается с самим собой.","refs":["E4"]}`. Для неизвестного запиши `"band":null` и `"basis":"unknown"`, объясни, что предстоит узнать. У каждого варианта заполни сильную сторону и свяжи её с основанием. В `next_evidence` укажи ближайшее наблюдение, которое может поменять сравнение.

## Что означает число

Четыре вопроса различаются по содержанию. Получит ли клиент лучший результат? Изменится ли чистый вклад? Успеваем ли выполнить действие к сроку? Что узнаем для следующего решения? Они могут зависеть от одних исходных данных. Охват, открытие уведомлений и удержание учитывай внутри причинной цепочки. Автоматическое добавление всех трёх в качестве новых критериев дало бы одному механизму лишний вес.

Для каждого профиля нижняя и верхняя суммы считаются отдельно по формуле **Σ(вес × балл / 4)**. Сумма весов — 100, балл критерия — от 0 до 4. Балл 3 при весе 25 даёт 18,75 из 100. Для неизвестного вклада при том же весе границы составят 0–25. Баллы ранжируют по выбранной шкале. Это экспертная модель, её интервалы не оценивают статистическую вероятность или ожидаемую прибыль.

Профили «равные веса», «экономика» и «срок» — исходные предложения. При наличии предпочтений руководителя сохрани копию рубрики с новой версией и запускай с `--rubric work/my-case/rubric.json`. В `scoring.json` впиши ту же версию. В первом профиле отчёт показывает взвешенный вклад каждого критерия, во всех профилях — итоговые диапазоны.

Вариант с нарушенным обязательным условием исключается из выбора. Вариант с открытым условием участвует в сравнении как возможный конкурент. Лидер профиля должен сам пройти проверку и иметь нижнюю границу выше верхней границы каждого другого допустимого или ещё проверяемого варианта. При пересечении диапазонов вывод открыт. Устойчивый лидер должен оказаться первым по этому правилу во всех заявленных профилях. Это консервативная проверка при имеющихся границах и допущениях.

## Расчёт и пересмотр

```sh
python3 tools/score.py work/my-case
```

Для записи перенаправь вывод в файл, например `scorecard-v1.md`. Первая таблица предназначена руководителю. Под ней видны веса, причины диапазонов, возражения и ограничения.

Когда появился новый источник, присвой ему новый ID, сохрани предыдущую оценку, измени затронутые диапазоны или условия и пересчитай таблицу. В журнале запиши, что изменилось, какие варианты поменяли положение и какой следующий выбор требует человека. Утверждение о финансировании заноси в `state.json` только после явного ответа руководителя.

На управленческом слайде и в короткой таблице у каждого варианта одно число. Берём середину его минимального и максимального итога по основному профилю, округляем до целого, половины вверх. Пример для двух пилотов: (12,5 + 93,75) / 2 = 53,125 → 53. Это условный ориентир по шкале, а не вероятность успеха. Полный интервал, жёсткие условия и другие веса остаются в подробном расчёте.

**Как объяснить результат руководителю.** В примере оператора четыре критерия равновесны. Для двух пилотов границы от 12,5 до 93,75 дают середину 53,125, на слайде отображается 53/100. При пробеле ширина интервала сохраняется. Сильное возражение и обязательный допуск видны в карте. Один учебный факт о клиентском эффекте поднял семейную оценку до 59 при равных весах; данных о допустимости и экономике всё ещё не хватило для устойчивого лидера. Это отдельная проверка на копии дела. В рабочем состоянии выбор диагностики сделан человеком. [Расчёт по профилям и исходные допущения](../demo/family/first-run/scorecard.md)
